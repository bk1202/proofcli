# The 30-second demo

[Download/watch the revised MP4](https://github.com/bk1202/proofcli/releases/download/v0.4.0/proofcli-demo-v2.mp4).

The silent, captioned walkthrough runs for exactly 900 frames at 30 fps. It starts with the command and success message, compares the input CSV with the actual export, then follows ProofCLI's failed assertion. Camera pushes, value highlights, and short captions guide attention. There is no introductory title card or simulated installation output.

The terminal/file views replay actual command results with edited timing; they are not a continuous desktop screen recording. `demo/src/evidence.json` is generated by executing the exporter and CLI in a fresh staged directory. It includes the real commands, both CSV contents, messages, exit codes, and mismatches. The composition reads those values directly; selected report fields are labelled as an excerpt. This demonstrates missing assertions in CI, not a claim that CI or other testing tools cannot verify data.

Revision 2 is a separate release asset with its own `proofcli-demo-v2.SHA256SUMS`. The original release video and package checksums remain available. The README and release notes point to the revised cut.

To reproduce from the repository root, with Python 3.10+ and Node.js 22+:

```console
python tools/capture_demo.py
cd demo
npm ci
npm run lint
npm run dev
```

Open the printed Studio URL. To export the video:

```console
npm run render
npm run poster
```

The output is `demo/out/proofcli-demo.mp4`; the poster is `demo/out/demo-poster.png`. Dependencies are locked in `demo/package-lock.json` and are used only to build the video. The Python package and GitHub Action do not install them.

`demo-video.yml` renders pull-request previews and publishes the named revision after merge to main. It refuses to replace an existing asset. Future edits must use a new revision filename and matching links instead of overwriting published bytes. This media workflow does not trigger a Python package release.

[The hosted demo workflow](../.github/workflows/demo.yml) intentionally has a successful ordinary job and a failed ProofCLI job. Its failed overall result is the expected demonstration. The separate validation workflow asserts that same failure and remains green only when ProofCLI rejects the broken export.
